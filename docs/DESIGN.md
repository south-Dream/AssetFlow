# AssetFlow — 项目开发设计说明 V1.0

## 1. 项目简介

**项目名称：** AssetFlow

**项目类型：** Windows 桌面资源处理软件

**主要用途：** 为游戏开发、UI 制作、动画制作以及数字素材处理提供统一的资源加工与自动化流水线。

**开发目标：**

- 将常用资源处理功能集中到一个软件中。
- 支持单文件和批量资源处理。
- 通过处理器注册机制与数据驱动实现功能扩展。
- 未来支持节点式工作流，将多个操作自由组合。
- 支持 AI 模型按需下载、加载、切换和卸载。
- 支持图片、视频、音频、动画等多种资源类型。
- 为 Unity 等游戏引擎提供资源适配与导出能力。
- 软件核心功能在本地离线运行，不依赖云服务器。

**开发原则：先完成可用功能，再逐步扩展，不追求第一版实现全部系统。**

## 2. 技术架构

### 2.1 技术选型

| 模块                   | 技术                  |
| ---------------------- | --------------------- |
| 桌面程序               | Electron              |
| 前端界面               | React + TypeScript    |
| 项目构建               | Vite                  |
| 图片处理               | Sharp / libvips       |
| 桌面安装包             | Electron Forge        |
| 节点画布（后续）       | React Flow            |
| AI 图像处理（后续）    | Python / ONNX Runtime |
| 视频与音频处理（后续） | FFmpeg                |
| Unity 适配（后续）     | C# Editor 扩展        |

V0.1 阶段只集成基础图片处理所必需的依赖。

暂时不要引入 Python AI、FFmpeg 和节点编辑器的完整实现。

### 2.2 架构设计

采用以下层级：

**UI 表现层**

负责资源列表、预览、参数面板、任务状态、工作流编辑。

**应用服务层**

负责资源索引、软件配置、处理任务管理、预设加载、进度通知和文件导入导出。

**处理调度层**

负责按指定顺序执行处理器、处理批次、管理错误和取消任务。

**处理器层**

提供独立的图片处理器，以及后续的 Python、FFmpeg、动画与 Unity 适配器。

**外部能力层**

包括 Sharp、AI 模型、FFmpeg 和其他外部处理依赖。

各层通过明确接口通信，避免 UI 直接依赖具体算法实现。

## 3. 核心设计原则

### 3.1 数据驱动

所有可变内容优先使用配置和注册机制管理。

例如：

- 处理器列表由注册信息生成。
- 分类由注册信息生成。
- 处理器参数由 Schema 描述。
- UI 根据处理器类型与参数生成常规属性编辑器。
- AI 模型列表从模型配置读取。
- 工作流由 JSON 配置保存。
- 功能预设通过数据动态加载。

禁止在 UI 中写死具体处理器、模型或软件列表。

但不能为了数据驱动而把实际算法写进 JSON。

### 3.2 模块化

每个处理器是独立实现，例如：

- ResizeProcessor
- CropProcessor
- TrimProcessor
- RotateProcessor
- ConvertProcessor
- RenameProcessor

同类功能允许共用底层处理逻辑。

不要为简单操作增加多余的包装类。

处理器应通过统一注册表暴露，不需要让 UI 认识每个具体实现。

### 3.3 可扩展性

系统需要方便增加：

- 新图片处理器
- 新资源格式
- 新处理引擎
- 新模型适配器
- 新节点类型

增加同类处理器原则上只需要注册新处理器及其 Schema，不应修改通用 UI 和任务调度逻辑。

### 3.4 统一入口

提供一个统一的 ProcessingRegistry，管理处理器的注册、能力描述和调用。

未来模型使用独立的 ModelRegistry 和 ModelAdapter，不必将不同职责全部塞进一个巨大管理类。

### 3.5 安全性

- 默认不修改原始资源。
- 处理失败不能破坏原始文件。
- 不允许不可信配置直接执行任意命令。
- 文件输出前检查路径是否合法。
- 新增外部程序和 AI 模型需验证来源与文件完整性。
- Electron 使用 contextIsolation 和安全 Preload API。
- 关闭不必要的 Node 集成，不直接向渲染页面暴露完整文件系统权限。

## 4. V0.1 — 基础图片处理工作台

第一阶段只开发以下内容。

### 4.1 文件导入

支持：

- 拖拽图片文件。
- 多文件选择。
- 导入文件夹。
- 可选递归读取子文件夹。
- PNG、JPEG、WebP 格式。
- 显示资源缩略图与基本属性。
- 显示文件名、分辨率、格式和文件大小。
- 自动识别无法解析的文件。
- 支持从资源列表移除文件。

使用文件路径与元数据管理资源，避免把全部图片一次性完整解码到内存中。

### 4.2 图片操作

**裁剪 Crop**

- 使用像素坐标进行裁剪。
- 支持可视化裁剪区域。
- 支持指定宽度和高度。
- 超出图像范围时进行参数校验。

**缩放 Resize**

- 固定宽高。
- 指定缩放比例。
- 限制最大边长。
- 保持长宽比。
- 提供不同插值模式，包含适合像素画的最近邻模式。

**画布调整 Canvas / Padding**

- 指定目标画布尺寸。
- 指定边距。
- 设置对齐方式。
- 设置背景颜色或透明背景。
- 图片内容可以居中或按指定位置放置。

**旋转 Rotate**

- 90°、180°、270°。
- 自定义角度。
- 水平翻转、垂直翻转。

**透明裁剪 Trim**

- 根据 Alpha 通道识别内容边界。
- 自动裁剪透明区域。
- 支持 Alpha 阈值。
- 支持额外保留边距。
- 对完全透明或没有 Alpha 通道的图片提供明确处理策略。

**格式转换 Convert**

- PNG。
- JPEG。
- WebP。
- 格式质量参数。
- 透明图片转换成 JPEG 时可配置背景色。

**文件命名 Rename**

- 添加前缀。
- 添加后缀。
- 添加递增序号。
- 替换指定字符。
- 根据模板生成文件名。

### 4.3 批量处理

- 支持对多个资源执行同一组处理操作。
- 使用可排序的操作步骤列表。
- 处理步骤支持启用、关闭和删除。
- 操作执行顺序可调整。
- 批量任务支持进度显示。
- 支持取消任务。
- 单个文件失败不应无故终止整个批次。
- 支持显示失败原因。
- 控制并发数量，避免同时解码过多高分辨率图片。
- 支持保存和读取处理预设。

### 4.4 图片预览

- 原始图片预览。
- 处理后预览。
- 前后切换或对比。
- 图片缩放、平移。
- 适应窗口显示。
- 显示处理前后尺寸和预计输出格式。

预览尽量复用真实处理逻辑，不允许预览结果与实际导出结果采用两套不一致的算法。

### 4.5 资源导出

- 导出到指定文件夹。
- 批量导出。
- 可选择保留原始目录结构。
- 可配置文件命名规则。
- 文件重名检测。
- 默认禁止覆盖原始图片。
- 可选 ZIP 打包导出。
- 显示处理完成后的统计结果。

对于已经存在的输出文件，应明确提示或按配置生成不冲突的名称。

## 5. V0.2 — 工作流系统

在 V0.1 处理器可稳定运行后，开发节点编辑器。

### 5.1 节点编辑器

支持：

- 添加和删除节点。
- 拖动节点。
- 连接节点输入输出。
- 编辑节点参数。
- 缩放与平移画布。
- 框选多个节点。
- 保存和加载工作流 JSON。
- 展示运行状态。
- 展示节点错误信息。

### 5.2 工作流执行

工作流基于有向无环图（DAG）。

执行器负责：

- 检查输入输出端口类型。
- 检测循环依赖。
- 根据依赖确定执行顺序。
- 处理批量资源集合。
- 支持分支与结果合并。
- 提供节点执行状态。
- 控制运行并发与内存使用。
- 支持执行取消与错误处理。

后续加入条件节点与过滤器。

### 5.3 工作流预设

工作流保存为 JSON。

初始预设：

- 图片统一尺寸。
- 批量透明裁剪。
- UI 图标标准化。
- 图片批量格式转换。
- 游戏资源批量命名。

工作流配置与运行时资源数据分离。

不在 JSON 中存储大量图片的二进制内容。

## 6. V0.3 — 游戏资源与动画处理

### 6.1 SpriteSheet

- 按固定宽高切图。
- 按行列切图。
- 根据透明区域辅助切图。
- 手动切割线。
- 自动图集打包。
- 图集边距和 Padding。
- 图集坐标元数据导出。

### 6.2 动画处理

- 图片序列导入。
- 帧顺序管理。
- 帧率设置。
- 循环播放预览。
- 帧画布对齐。
- Pivot 数据调整。
- 动画帧批量导出。
- GIF / APNG 支持按独立功能逐步增加。

透明裁剪必须保留必要的偏移信息，避免逐帧动画因画布变化产生抖动。

### 6.3 Unity 适配

通过独立 Unity Editor 插件完成：

- Sprite 导入配置。
- Sprite Pivot 配置。
- Sprite Border 配置。
- SpriteSheet 切分信息导入。
- AnimationClip 生成。
- 后续扩展 Prefab 生成。

AssetFlow 负责输出图片与标准化元数据，Unity 插件负责调用 Unity Editor API。

## 7. V0.4 — AI 模型管理与智能图片处理

### 7.1 模型管理器

AI 模型不直接打包进基础 EXE，采用按需下载方案。

模型配置包含：

- ID。
- 显示名称。
- 模型类型。
- 模型版本。
- 下载地址。
- SHA-256 校验信息。
- 对应适配器。
- 运行后端。
- 设备要求。
- 输入输出规范。
- 推荐参数。
- 授权信息。

模型列表由配置动态生成。

支持：

- 查看模型。
- 下载模型。
- 显示进度。
- 安装状态检查。
- 切换模型。
- 删除模型。
- 导入受支持的本地模型。
- 管理模型存储目录。

不兼容模型应显示具体原因，而不是在管理器中直接消失。

### 7.2 模型适配器

不同模型通过 ModelAdapter 对接统一处理接口。

优先支持：

- ONNX Runtime。
- Python 智能处理模块。

适配器负责：

- 加载模型。
- 输入预处理。
- 运行推理。
- 输出后处理。
- 模型释放。
- 错误状态。
- 批量处理。

模型配置只能引用已注册的适配器，不允许配置文件直接指定任意可执行代码。

### 7.3 智能功能

逐步增加：

- AI 去背景。
- 自动主体分割。
- 多元素识别与切分。
- 边缘修复。
- 前景 Alpha 优化。

AI 模型在当前版本不支持时应提供正常降级或明确提示。

## 8. V0.5 — 视频与音频处理

通过 FFmpeg 等底层库提供：

**视频**

- 视频导入。
- 指定时间区间。
- 按固定帧率抽帧。
- 按固定时间间隔抽帧。
- 视频转图片序列。
- 图片序列转视频或 GIF。

**音频**

- 音频格式转换。
- 音频裁剪。
- 静音段处理。
- 音量归一化。
- 批量音频处理。

这些功能通过独立处理器接入已有执行系统。

## 9. 桌面 UI 设计

采用专业资源处理工作台风格。

**顶部工具栏**

文件导入、目录导入、预设、运行、导出、设置。

**左侧资源面板**

显示已导入资源、缩略图、尺寸、格式和状态。

**中央预览区**

显示原图、处理结果、透明网格背景、缩放与平移。

**右侧处理面板**

V0.1 为处理步骤列表与参数编辑。

V0.2 增加节点编辑工作区模式。

**底部任务面板**

显示执行进度、当前资源、成功数量、错误数量和日志。

支持深色与浅色主题。

各主要工作区域支持调整宽度。

不要为了视觉效果牺牲操作效率。

## 10. 项目目录建议

```
AssetFlow/
├── scripts/src/
│   ├── main/             # Electron 主进程
│   ├── preload/          # 安全 IPC 接口
│   ├── renderer/         # React UI
│   ├── core/
│   │   ├── assets/       # 资源管理
│   │   ├── processors/   # 处理器
│   │   ├── pipeline/     # 流水线执行
│   │   ├── tasks/        # 任务管理
│   │   └── registry/     # 注册管理
│   ├── services/         # 应用服务
│   ├── types/            # 类型定义
│   └── config/           # 默认配置
├── presets/              # 内置处理预设
├── docs/                 # 设计文档
├── tests/                # 自动化测试
└── package.json
```

这只是建议结构。

Codex 可以根据实际构建工具调整路径，但必须确保 Electron 主进程、React 渲染进程和处理核心职责清楚。

不要一开始创建大量暂时没有实现的空类和空文件夹。

## 11. 开发实施要求

本项目采用分阶段开发。

当前只实施 **V0.1 基础图片处理工作台**。

开发流程：

1. 初始化 Electron + React + TypeScript 项目。
2. 实现主窗口与基础布局。
3. 实现资源导入和缩略图预览。
4. 完成各项图片处理器。
5. 建立统一处理器注册接口。
6. 完成可排序处理步骤和参数面板。
7. 完成批量任务执行。
8. 完成预设配置读写。
9. 完成目录导出与 ZIP 导出。
10. 编写必要的自动化测试。
11. 构建 Windows 应用并验证运行。
12. 编写 README 和开发文档。

第一阶段不需要实现完整节点系统、AI 模型下载和 FFmpeg 功能。

但处理模块应预留未来的统一扩展接口。

## 12. V0.1 验收标准

必须验证：

- 可以正常打开 Windows 桌面软件。
- 可以批量导入图片及目录。
- 可以正确执行裁剪、缩放、透明边裁剪、旋转、补边。
- 可以转换 PNG、JPEG、WebP。
- 可以进行批量重命名。
- 可以调整处理步骤顺序。
- 可以保存和加载预设。
- 可以预览真实处理结果。
- 可以导出指定目录。
- 可以导出 ZIP 文件。
- 不会未经确认覆盖原始图片。
- 处理失败能定位文件并报告错误。
- 可以取消批量处理。
- 可以正常退出并释放资源。
- 能够打包生成 Windows 可运行程序。

至少提供典型图片样本和异常情况的测试结果。

最终交付：

- 完整项目源码。
- README。
- 本地开发说明。
- Windows 构建说明。
- 能成功构建的安装包或便携版。
- 已完成和未完成的功能清单。

**优先保证正确性、稳定性和模块边界，避免只做出功能齐全但实际不可用的界面。**
