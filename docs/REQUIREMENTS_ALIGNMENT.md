## 1. 总体判断

当前产品是 **AssetFlow 单窗口图片批处理工作台**；新规划是 **AssetTool 模块化游戏资产工作台**。Electron + React + TypeScript + Sharp 可以沿用，无需重写现有图片处理器和可视化编辑器。

新规划最主要的增量是 Core、PkgMgr、完整 Module SDK、多工具实例、统一任务服务和 ExportProfile。基础图片能力已有较好覆盖，图像流水线甚至提前实现了部分 V0.2 内容；本地 rembg 也已接入，但模型管理与全局调度尚不完整。因此，不能把当前包版本 `0.1.0` 等同于新规划 V0.1 已交付。

### 任务系统需要从现有批处理升级

当前 `scripts/src/main/index.ts` 用全局 `running`、`cancelled`、`workers` 和 `activeBatch` 管理一个批次，固定两路处理；第二个批次直接被拒绝。已有完成数进度、取消、逐文件失败隔离和界面错误列表，但没有任务 ID、排队列表、历史、失败项重试或独立任务日志。

需要引入 TaskManager，使提交参数、输入引用和输出配置形成任务快照；任务状态由主进程管理，面板只订阅。关闭工具标签后任务继续，重新打开任务面板可恢复进度。整个应用退出时当前会取消 Worker；新文档明确要求的是关闭面板不终止任务，应用退出策略可另行定义。

并发和取消也需调整：

- 当前预览与导出共享 `workers`，取消批次会终止其中所有 Worker；应按任务和实例取消。
- 当前预览以 `original/processed` 为键替换旧 Worker；多实例后会互相打断，需加入实例 ID。
- `InferenceService` 在自身实例内串行，但 `removeBackground` 每次调用都会创建新服务，批处理又在不同 Worker 中执行；这不能保证全局 AI 串行。应由统一调度器限制 AI/视频等重型任务，并把预览纳入资源预算。
- 现有进度主要按文件计数，处理流程的 `reportProgress`/`log` 目前未接入统一任务记录；需要补齐步骤错误、时间和结构化日志。

## 6. 建议实施顺序与验收边界

### 第一批：补齐新规划 V0.1 的底座

1. **Core 与工作区**：分离应用壳和 ImageTool；增加首页、导航、设置、多标签实例。验收：两个图像实例的资源、步骤、预览互不干扰。
2. **TaskManager**：独立任务 ID、队列/状态、取消/失败重试、结构化日志、全局资源并发。验收：关闭标签任务继续；取消一个任务不打断另一个实例预览；AI 峰值遵循统一限制。
3. **ExportProfile 与导出规划**：三模式、分类与人工调整、命名、冲突策略、目录/文件预览、Manifest。验收：预览与实际映射一致，源文件默认不变，重名与非法路径可追溯。
4. **Module SDK 与 PkgMgr**：补全模块契约和可信安装流程；可先交付本地 ZIP，再接官方静态清单与下载，但新规划首期验收仍须覆盖官方包、依赖与校验。验收：不兼容/损坏/不可信模块被拒绝；安装失败不破坏已安装版本；启停影响导航和能力注册。
5. **ImageTool V0.1 补齐与桌面验收**：选择子集、命名与导出预览、透明丢失提示及基础编辑缺口；浏览高级功能按完整需求继续排期。

可先定义 Task、ToolInstance、AssetRef、ModuleManifest、ExportProfile 之间的契约，再分批接入，避免在当前 App 和主进程里继续堆全局状态。

### 第二批：V0.2 媒体与工作流

Sprite Sheet、Atlas、传统色键、流水线增强、AudioTool、VideoTool、分屏停靠与布局保存。现有流水线与 rembg 保留复用，不必因路线表列到后续就删除已有能力。

### 第三批：V0.3 / V0.4

DataTool、AnimationTool、浮动窗口/多显示器、跨窗口引用；再完善 AI 模型管理、Unity Editor 集成、规范扫描/去重、第三方仓库、更新与回滚。

需求原稿 §5.11 将 AI 等列为“V0.3 及以后”，§12 全局路线列为 V0.4；建议实施排期按 §12 全局路线统一，并注明 AI 基础接入已提前存在。
