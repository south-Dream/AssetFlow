# AssetTool 产品规划与功能需求文档

-   **版本：** V0.1 规划稿
-   **定位：** 面向游戏开发者的模块化资产处理工作台
-   **建议技术栈：** Electron + React +
    TypeScript；重型任务使用独立进程或外部工具
-   **首期重点：** Core、PkgMgr、Module SDK、通用任务系统、ImageTool

------------------------------------------------------------------------

## 1. 产品定位

AssetTool
不只是把图片、音频、视频转换功能放在一起的工具箱，而是统一的游戏资产工作台：

> 导入资产 → 识别与整理 → 批量处理 → 预览检查 → 按项目规范组织 →
> 导出到游戏工程。

核心原则：

1.  **模块化：**
    图像、音频、视频、数据、动画等模块可独立安装、更新和卸载。
2.  **统一入口：** Core
    负责导航、文件访问、任务队列、日志、设置和工作区。
3.  **批处理优先：** 支持多文件、整个目录、处理预设和一键重复执行。
4.  **配置驱动：** 目录模板、命名规则、处理流程和模块信息由配置管理。
5.  **安全导出：** 默认不覆盖原文件；导出前预览路径和冲突。
6.  **任务与窗口解耦：** 关闭面板不应自动终止已提交的后台任务。
7.  **重型任务隔离：** 视频转码、AI 推理等通过独立进程或外部工具运行。
8.  **先闭环后生态：** 初期只支持官方模块，后续再考虑第三方插件。

## 2. Core 与 PkgMgr

### 2.1 AssetTool Core

Core 是统一的桌面工作环境，提供：

-   主窗口、首页、导航、菜单栏和设置。
-   模块注册与 Module SDK。
-   文件选择、目录浏览、资产引用和临时文件管理。
-   统一任务队列、进度、取消、错误日志和重试。
-   导出配置、命名规则、目录模板与冲突策略。
-   工作区布局保存、恢复、多窗口管理。
-   统一通知、日志、诊断和版本兼容检查。

Core 不必内置所有资产处理功能；具体功能通过模块按需安装。

### 2.2 PkgMgr 模块包管理器

通过左上角菜单或侧栏打开 PkgMgr，浏览可用模块。

**首期功能：** - 模块列表、简介、版本、体积、兼容的 Core/API 版本。 -
安装、卸载、启用、禁用。 - 下载进度、完整性校验和失败提示。 - 本地 ZIP
模块安装。 - 依赖检查、已安装运行时复用。 - 已安装模块列表和版本显示。

**后续功能：** - 模块更新、回滚、更新日志。 - 依赖关系与冲突处理。 -
多渠道仓库和第三方模块发布。 - 大型 AI 模型包与运行时分开管理。

建议先用静态 Manifest JSON + ZIP
文件分发，不需要第一版就搭建复杂服务端。安装时先下载到临时目录，校验通过后再切换为正式版本。

### 2.3 模块 Manifest

每个模块清单建议包含： -
`id`、`name`、`version`、`description`、`category`。 -
`apiVersion`：兼容的 Module SDK 版本。 - `entry`：模块入口。 -
`dependencies`：模块和运行时依赖。 - `capabilities`：模块提供的能力。 -
`permissions`：需要的文件或外部进程权限。

模块不应互相依赖内部实现；统一通过
SDK、资产引用和任务服务交互。初期仅加载可信官方模块，不要把未知来源的
JavaScript 当作可信代码执行。

## 3. 自由工作区与多窗口

### 3.1 窗口能力

-   **标签页：** 在主窗口内切换多个工具实例。
-   **停靠面板：** 支持拖动、分屏、调整尺寸、标签分组。
-   **浮动窗口：** 面板拖出主工作区后成为独立 Electron `BrowserWindow`。
-   **多显示器：** 浮动窗口可放到第二块屏幕。
-   **布局预设：** 保存和恢复图像处理、UI 制作、视频处理等工作区。

### 3.2 开发顺序

1.  V0.1：单主窗口、多标签页、多个工具实例。
2.  V0.2：分屏、停靠、调整尺寸、布局保存。
3.  V0.3：独立浮动窗口、多显示器恢复。
4.  后续：跨窗口资产拖拽和面板联动。

React 组件不能直接跨两个 BrowserWindow
原样移动；浮动时应创建新页面实例，并恢复可序列化的面板状态。

### 3.3 四窗口示例

可以同时打开图像预览、图集编辑、序列帧预览、Unity
资源目录；也可以组合视频裁剪、抽帧、音频编辑和图片处理。

窗口数量不等于任务并发数。Task Manager 应统一限制视频转码、AI
推理等重型任务，避免占满 CPU、内存或显存。

### 3.4 跨窗口资产拖拽

模块之间传递资产引用，不重复复制大型二进制文件。统一结构示例：

``` ts
interface AssetRef {
  id: string;
  path: string;
  type: string;
  metadata?: Record<string, unknown>;
}
```

典型流程： - 视频抽帧 → 图像裁剪 → 序列帧动画。 - 图像处理 → 图集打包 →
导出 Unity。 - Excel 转 JSON → 按项目模板整理导出。

## 4. 资产分类与导出

### 4.1 三种导出模式

**A. 按资产大类优先（默认）**

``` text
Assets/Resources/
├── Images/
│   ├── Player/
│   ├── UI/
│   └── Environment/
├── Audio/
│   ├── BGM/
│   └── SFX/
├── Animations/
├── Models/
└── Configs/
```

**B. 按游戏系统优先**

``` text
Assets/Resources/
├── Player/
│   ├── Images/
│   ├── Animations/
│   └── Audio/
├── UI/
│   ├── Images/
│   └── Audio/
└── Environment/
    ├── Images/
    └── Models/
```

**C. 零散导出**

不创建额外分类目录，直接输出到用户指定位置。

### 4.2 自动分类

分类分三层： 1. **类型识别：** 扩展名、文件头、媒体元数据。 2.
**用途识别：** 原始目录、命名规则、用户标签、手动选择。 3.
**目录映射：** 根据当前 ExportProfile 生成目标路径。

不能只根据扩展名猜业务用途：PNG 可能是
UI、角色贴图、动画帧或图集。无法确定时放入
`Uncategorized`，并在导出预览中让用户调整。

### 4.3 ExportProfile

每个项目保存独立预设，包含： - 目标根目录和目录模板。 -
资源分类规则、目录映射。 - 命名规则、前后缀、序号。 -
格式转换与尺寸规则。 - 未分类资源的去向。 -
冲突策略：覆盖、跳过、自动重命名。 - 是否保留源目录结构。 - 是否生成
Manifest。 - 是否允许输出到 Unity `Resources`。

资源类型和业务归属分开记录。例如：类型 Image、归属 Player、用途
AnimationFrame，最后映射到 `Images/Player/Animation/`。

### 4.4 Unity 路径注意事项

`Assets/Resources` 是可选模板，不应硬编码为唯一输出目录。Resources
有特殊加载行为，放入其中的资源可能影响构建体积和资源管理。应同时提供
`Assets/GameAssets/`、自定义目录等模板。Addressables
目录模板也不能仅靠目录名就视为完成了 Addressables 配置。

### 4.5 导出安全与复用

-   导出前预览目录树和文件清单。
-   检查重名、覆盖、非法路径和未分类资源。
-   支持覆盖、跳过、自动重命名。
-   保存输入输出映射与处理参数。
-   原素材更新后可以按原预设一键重新处理。
-   可生成 Manifest 记录源路径、输出路径、参数、时间、结果和错误。

## 5. ImageTool 图像模块（重点）

图像是第一优先级模块。目标是覆盖从导入、基础处理、去背景、切片、图集打包，到按项目规范导出的完整流程。

### 5.1 导入与浏览

-   单图、多图、整目录导入，支持递归子目录。
-   拖放文件和文件夹。
-   常见格式：PNG、JPG/JPEG、WebP、BMP、TIFF（具体取决于解码库）。
-   显示缩略图、名称、尺寸、格式、文件大小、色彩模式、Alpha 通道。
-   网格、列表、详细信息视图。
-   搜索、筛选、排序。
-   识别损坏或无法解码的文件并说明原因。
-   保留原始路径，支持按原目录结构导出。

### 5.2 预览与对比

-   适应窗口、实际像素、放大、缩小、平移。
-   透明背景棋盘格和纯色背景切换。
-   原图与处理结果前后对比。
-   左右对比或分割线对比。
-   查看尺寸、体积和 Alpha 信息。
-   批量选择时快速切换图片。
-   预览操作不修改原文件。

### 5.3 基础编辑

**缩放** - 指定宽高、百分比、最长边或最短边。 -
保持比例、目标尺寸预设。 - 选择重采样质量。

**裁剪** - 自由裁剪、固定宽高比、指定像素坐标。 - 目标尺寸居中裁剪。 -
批量复用同一裁剪参数。 - 裁剪区域实时预览。

**旋转与翻转** - 90°、180°、270°、自定义角度旋转。 -
水平翻转、垂直翻转。 - 旋转后透明区域处理选项。

**补边与画布调整** - 扩展画布、设置上下左右补边像素。 -
指定目标画布宽高。 - 对齐方式：居中、左上、底部居中、自定义锚点。 -
透明或纯色填充。 - 多图统一画布，适用于角色立绘、图标、序列帧。

**透明边裁剪** - 自动裁剪透明边。 - Alpha 阈值，处理接近透明的边缘。 -
可保留安全边距。 - 显示裁剪前后的边界。 - 批量处理。 -
对不含透明通道的图片给出提示。

**画布对齐** - 多图统一尺寸。 - 按中心、底部或自定义参考点对齐。 -
预览对齐结果。

### 5.4 格式转换与压缩

-   PNG、JPEG、WebP、BMP 等互转。
-   透明度丢失提醒。
-   JPEG/WebP 质量参数。
-   预估输出体积（可选）。
-   批量转换、重命名和导出。
-   保留或移除元数据。
-   单文件失败不影响整个批次继续执行。

### 5.5 去背景与背景处理

-   纯色背景取样去除。
-   色差容差、边缘平滑和羽化。
-   Alpha 边缘预览，减少白边或黑边。
-   透明背景导出。
-   纯色背景替换。
-   可选 AI 去背景模块。
-   AI 模型独立下载、版本管理和缓存。
-   AI 模块不可用时，基础图像功能仍能使用。
-   支持原图与结果对比、重新调整参数。

传统色键适合纯色背景；复杂背景应使用可选 AI
模型，不能把两者当作相同质量的功能。

### 5.6 图片合并与拆分

-   多图横向、纵向合并。
-   网格拼图。
-   设置列数、间距、边距和背景。
-   合并前统一尺寸或保留原尺寸。
-   按网格、固定宽高或指定坐标拆分。
-   可选自动识别透明区域中的独立图块。
-   切片命名模板，例如 `{name}_{index}`。
-   导出切片坐标和尺寸元数据。

### 5.7 Sprite Sheet 自动切片

-   按行列数或单格宽高切片。
-   起始偏移、横纵间距、边距设置。
-   指定读取顺序。
-   跳过空白格。
-   按 Alpha 边界裁剪每帧。
-   预览网格线、编号和选中帧。
-   单帧检查、批量重命名。
-   导出 PNG 序列和坐标 JSON。
-   规则 Sprite Sheet 与不规则图集采用不同模式。

### 5.8 图集打包 Atlas

-   导入多张独立图片并自动排列。
-   设置图集最大宽高、间距和外边距。
-   是否允许旋转、是否裁剪透明边。
-   保留原尺寸或统一尺寸。
-   预览图集布局与占用率。
-   导出 PNG/WebP 图集和 JSON 坐标。
-   坐标数据包含位置、尺寸、原始尺寸、偏移和旋转状态。
-   按标签、目录或命名规则拆分多个图集。
-   检查超出尺寸限制的图片。
-   支持重新打包和稳定命名。

**Unity 辅助：** - 导出 Sprite 切片元数据。 - 配置和预览 Pivot/锚点。 -
预览九宫格切片与边界。 - 为自定义 Unity Editor 导入脚本生成数据。 -
PNG + JSON 不等于自动完成 Unity SpriteAtlas 的全部设置；真正的 Unity
集成可由后续 Editor 插件实现。

### 5.9 批量命名

-   添加前缀、后缀和序号。
-   字符串替换。
-   统一大小写和分隔符。
-   高级模式支持正则表达式。
-   根据目录、标签或用途生成输出路径。
-   导出前预览最终文件名。
-   检查重名和非法字符。

### 5.10 图像处理流水线

允许用户组合并保存一套可复用流程。例如：

``` text
导入角色图片
  → 自动裁剪透明边
  → 保留 4px 安全边距
  → 统一画布为 256×256
  → 缩放到目标分辨率
  → 重命名为 Player_Idle_001.png
  → 导出到 Images/Player/Animation/
```

-   步骤可排序、启用、禁用。
-   每一步可预览参数。
-   支持单图、选中项和整个目录。
-   保存预设并重复运行。
-   记录失败步骤和错误原因。
-   默认不覆盖源文件，除非用户明确选择。
-   原素材更新后按原规则重新导出。

### 5.11 图像模块版本规划

**V0.1 必做：** - 文件/目录导入、缩略图、预览、透明棋盘格。 -
缩放、裁剪、旋转、翻转、补边。 - 透明边裁剪。 - PNG/JPEG/WebP 转换。 -
批量重命名。 - 结果预览、批量导出。 - 目录模板与冲突处理。

**V0.2：** - Sprite Sheet 切片。 - 图集打包与 JSON 坐标导出。 -
色键去背景。 - 可复用图像处理流水线。

**V0.3 及以后：** - AI 去背景与模型管理。 - 更复杂的图集布局优化。 -
Unity Editor 集成、Pivot 辅助与自动导入。 - 资产规范扫描和批量修复。

## 6. AudioTool 音频模块（简要）

-   WAV、MP3、OGG、FLAC 等格式转换。
-   音频裁剪、分段、合并。
-   淡入淡出、音量调整和标准化。
-   声道转换、采样率调整。
-   波形预览、片段试听。
-   静音检测和自动裁剪。
-   音效目录连续试听、标记与批量重命名。
-   BGM、SFX、UI 音效分类导出。
-   检查时长、采样率、声道等信息。

音频模块不负责视频抽帧；视频中的音轨提取归入 VideoTool。

## 7. VideoTool 视频模块（简要）

-   格式转换、分辨率和帧率调整。
-   按起止时间裁剪。
-   按固定间隔、指定时间点或 FPS 抽帧。
-   导出 PNG/JPEG 序列帧。
-   视频转 GIF。
-   提取音轨、音视频分离。
-   缩略图和关键帧预览。
-   批量处理、进度、取消和错误日志。
-   使用 FFmpeg 等成熟工具完成编解码。
-   重型任务独立进程运行，并限制并发。

## 8. DataTool 文本与数据模块（简要）

**配置表** - Excel、CSV、JSON 转换。 -
字段类型、默认值、数组、嵌套数据处理。 - ID
唯一性、空值、类型错误和引用完整性检查。 -
表结构预览、转换报告、字段映射。

**代码生成** - 根据 Schema 生成 C# 类、C++ 结构体和枚举。 -
命名规则、代码模板、生成代码预览。 - Protobuf `.proto` Schema 生成与
`protoc` 编译流程。 - Excel 转 Protobuf
必须使用明确的字段映射和消息结构，不能只是改扩展名。

**剧情与文本** - 对话表查看和编辑。 - 多语言表格合并。 -
缺失翻译、文本长度和占位符检查。 - 对话 ID、剧情引用和变量命名检查。

## 9. AnimationTool 动画与模型模块（简要）

**2D 序列帧** - 导入 PNG 序列或 Sprite Sheet。 - 自动切片、帧排序、FPS
设置。 - 播放、暂停、单帧步进和循环。 - 时间轴、帧顺序调整。 -
预览锚点、透明边界和动画包围盒。 - 导出 PNG 序列、图集及动画 JSON。

**3D 模型浏览** - 优先支持 GLB/glTF。 - 旋转、缩放、平移、线框查看。 -
查看材质、贴图和骨骼层级。 - 播放已有骨骼动画、切换动画片段。 -
查看模型尺寸、面数和材质数量。 - FBX 后续通过适配器或 Blender
等外部工具支持。

首期只做预览、检查和转换，不做骨骼编辑、蒙皮权重、IK 或复杂动画状态机。

## 10. 通用资产管理与校验

-   文件类型识别和元数据读取。
-   命名规范检查。
-   重复资源检测（哈希；感知相似度可后续加入）。
-   缺失文件、损坏文件和非法路径检查。
-   图片尺寸、音频采样率、视频帧率等规则检查。
-   统一任务队列、进度、取消、重试和错误日志。
-   处理前后文件大小、格式和耗时对比。
-   导出 Manifest、保存任务预设和一键重新导出。

## 11. 推荐技术结构

-   **桌面端：** Electron + React + TypeScript。
-   **模块：** Module SDK + Manifest + 版本兼容检查。
-   **窗口：** Docking 布局库实现标签、分屏、停靠；Electron
    BrowserWindow 实现浮动窗口。
-   **任务：** Task Manager 管理队列、进度、取消、并发和日志。
-   **资产：** AssetItem 保存资源元数据；AssetRef 用于跨窗口引用。
-   **导出：** ExportProfile 保存目录映射、命名、格式与冲突策略。
-   **重型工具：** FFmpeg、AI 推理等由独立进程或 CLI 调用。
-   **安全：** 通过受控 IPC 通信，不向不可信模块暴露 Node.js 全权限。
-   **分发：** 模块 ZIP + Manifest 起步，模型与运行时按需下载。

## 12. 开发路线

### V0.1：最小闭环

-   Core：首页、导航、设置。
-   PkgMgr：安装、卸载本地或官方 ZIP 模块。
-   Module SDK：Manifest、注册入口、版本兼容。
-   Task Manager：进度、取消、错误日志。
-   ImageTool：基础操作、批量处理、预览和导出。
-   ExportProfile：目录模板、命名和冲突处理。
-   工作区先支持多标签页。

### V0.2：媒体处理扩展

-   图集打包、Sprite Sheet 切片。
-   AudioTool、VideoTool。
-   图像处理流水线与预设。
-   工作区分屏、停靠和布局保存。

### V0.3：数据与动画

-   DataTool：Excel、JSON、C#、C++、Protobuf。
-   AnimationTool：2D 序列帧、GLB/glTF 预览。
-   独立浮动窗口、多显示器。
-   统一资产引用和跨窗口拖拽。

### V0.4 及以后

-   AI 去背景和模型管理。
-   Unity Editor 集成。
-   资源规范扫描、重复资源检查。
-   第三方模块仓库、更新与回滚。
-   更多引擎和项目模板。

## 13. 非目标与风险

首期不做： - 替代 Photoshop、Blender、Spine 等专业软件。 - 完整 3D
建模、骨骼编辑、蒙皮、IK。 - 自行实现视频编解码器。 -
任意第三方代码执行。 - 复杂云端账号、付费和插件审核系统。

主要风险与控制： - **模块安全：**
下载包校验、权限控制、官方模块白名单。 - **文件安全：**
默认不覆盖源文件；写入前预览和冲突检查。 - **性能：**
统一限制重型任务并发。 - **兼容性：** Core 与 Module SDK 版本化。 -
**资源许可：** 记录第三方工具、字体、素材与模型许可。 - **目录误判：**
无法判断时交给用户确认。

## 14. 总结

AssetTool 是一个面向游戏开发者的模块化资产处理工作台：

-   **Core + PkgMgr：** 统一环境、按需安装模块。
-   **ImageTool：**
    第一核心模块，覆盖基础图片处理、去背景、切片、图集和批处理。
-   **AudioTool / VideoTool / DataTool / AnimationTool：**
    逐步扩展其他资产工作流。
-   **工作区：** 多标签、分屏、浮动窗口和布局保存。
-   **任务系统：** 后台并行处理、进度、取消和错误恢复。
-   **项目规范导出：** 按资产分类、按系统分类或零散导出。
-   **可扩展架构：** 模块独立安装和更新，重型处理与主界面解耦。

核心价值不是"功能数量多"，而是把游戏开发中零散、重复、手动的资产工作，变成统一、批量、可复用、可追踪的工作流。
